# 1.0 surface

The stability contract for [#242](https://github.com/Sannrox/mikura/issues/242).
Policy and rationale: [ADR 0042](../decisions/0042-api-stability.md).
How the crate works today: [architecture.md](../architecture.md).

This page lists what a 1.0 cut will freeze. It is not a 1.0 release.
crates.io stays `publish = false` until a human authorizes it
([#57](https://github.com/Sannrox/mikura/issues/57)).

Until 1.0, a breaking change on this list requires a minor bump
(`0.x` → `0.(x+1)`) and a CHANGELOG Upgrade note. After 1.0, Cargo
semver applies and removals need a deprecation window (ADR 0042).

Items not named here are not covered, even if they are `pub` today.

## Format versions

| Channel | Identifier | Rule after 1.0 |
| --- | --- | --- |
| Object log superblock | `MIKURAV2` (`mikura::LOG_FORMAT`); encrypted `MIKURAV3` (`LOG_FORMAT_ENCRYPTED`) | A later 1.x must open any 1.x `MIKURAV2` log. Encrypted logs are opt-in. A breaking magic or record body is 2.0. |
| Join sidecar | `MKJOIN06` (`JOIN_FORMAT`); `MKJOIN05` (`JOIN_FORMAT_V5`) still read | Rebuildable. Unknown magic fails closed; delete `{log}.joins` and reopen. |
| Join dirty-set | `MKJOIN6D` (`JOIN_DELTA_FORMAT`); `MKJOIN5D` (`JOIN_DELTA_FORMAT_V5`) still read | Same as the sidecar. |
| Log checkpoint | `MKCKPT01` (`CHECKPOINT_FORMAT`) | Unknown magic falls back (ADR 0034). |
| Encrypted snapshot envelope | `MKSEAL01` / `MKPART01` | Encrypted sidecars and checkpoints only. Store DEK wraps the tenant index; tenant DEKs wrap payloads (ADR 0044). |
| Restore point | `mkrp1:<commit point>:<page crc>` | Point-in-time restore (ADR 0037). |
| Host JSON envelope | `v` omitted or `1` (`mikura_host::WIRE_V`) | Unknown `v` fails closed. See wire rules below. |

Pre-1.0 `MIKURAV1` logs do not open. Migrate once with
`Store::migrate_unnamespaced`. That path is a compatibility tool, not a
1.0 open promise.

  `apply_overlay`, `hide`, `evaluate`, `load`, `health`, `metrics`
- CLI: `backup`, `verify`, `restore`
- Wire types: `HostRequest`, `HostResponse`, `HealthWire`,
  `EvaluateWire`, `WireEvaluate`, `WireHop`, `WireDeny`, `WireIdentity`,
  `WireRestriction`, `WireRowFilter`, `WireFilter`, `WirePredicate`,
  `WireBreakdown`, `WireGroup`, `WireSort`

Wire rules (ADR 0042): responses may add fields; new request fields are
optional with defaults; a new required request field or a removed `op`
is a wire break; unknown request keys and unknown `v` fail closed.

## Deprecation

- Pre-1.0: no deprecation window. A break still needs the minor bump and
  an Upgrade note.
- After 1.0: mark the old path `#[deprecated]` (and document the
  replacement) in a minor. Remove it only in a major. Host `op` names
  follow the same window: keep the old name at least one minor, then
  drop it in `v=2` or a crate major.
- CHANGELOG is the user-facing record. Keep a Changelog format stays.

## Registry and tags

Workspace crates stay version-aligned. Published dependents (`mikura-ingest`,
`mikura-host`) carry a version on their path deps so `cargo publish` can
resolve them after authorization. Public-API integration and 1.0 surface
lock tests live on `mikura-ingest`, so the root crate does not depend on
ingest even as a dev-dependency.

Release a version by the existing prepare-release path: bump the three
crate versions and the README status line, move `[Unreleased]` to the
new version, squash-merge, tag `v0.x.y` (or `v1.0.0` when authorized).
Pushing the tag runs `.github/workflows/release.yml` (tests + GitHub
Release). It does not publish to crates.io.

After a human sets `publish = true` and authorizes the first registry
push, `scripts/publish-crates.sh --yes` publishes `mikura`, then
`mikura-ingest`, then `mikura-host`. Until then `cargo add mikura` from
the registry is the remaining #57 step; consumers keep pinning a git
tag.
